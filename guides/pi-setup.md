# Gemcp Pi Agent Setup

This is a short-lived, one-time authorization flow generated by a Gemcp Owner. The complete link you received is a bearer capability until setup completes. Do not print it, commit it, include it in experiment arguments, or forward it to another person or Agent.

The setup code is stored only in the URL fragment (`#code=...`). Browsers do not include URL fragments in setup-page requests, access logs, or Referer headers. Merely opening or previewing this page does not consume the setup link.

A claimed setup credential is limited to `read` and expires with the setup link. The Owner-selected scopes and full credential lifetime activate only after all four verification checks complete.

## Pi Agent procedure

Complete these steps yourself. Do not ask the human to copy a Token or write MCP JSON.

1. Confirm the complete link starts with `{{GEMCP_PUBLIC_URL}}/agent/setup#code=`. Do not pass the complete link to a search, preview, or Web-fetch tool; request only `{{GEMCP_PUBLIC_URL}}/agent/setup` when reading these public instructions.
2. Confirm Node.js 20 or newer is available and `pi-mcp-adapter` is installed.
3. Run the fixed installer from the same trusted origin, passing the complete link as its only argument:

```bash
setup_link='<the complete setup link from the human message>'
curl --fail --silent --show-error --proto '=https' --tlsv1.2 \
  --user-agent 'Gemcp-Pi-Setup/1' \
  '{{GEMCP_PUBLIC_URL}}/agent/setup/install.mjs' \
  | node --input-type=module - "$setup_link"
unset setup_link
```

4. Require the final output to begin with `GEMCP_PI_SETUP_OK`, discover all seventeen direct tools, and report all four checks: `tools,guide,options,cost`.
5. The installer stores the bearer credential in the Pi agent directory's `mcp.json` with mode `0600`, stores a credential-free receipt, and installs a local Gemcp CLI for the current session.
6. Run `/reload` once when convenient. After reload, use the native `gemcp_*` tools. Before reload, use the `current_session_cli` command printed by the installer through Bash.
7. Never expose the stored credential. The setup link becomes unusable after successful verification.

## Required operating boundary

Setup and read-only verification do not create paid resources. For normal work:

- report only controlled workflow phases through `report_agent_activity`; never send prompts, reasoning, source contents, environment variables, or credentials;
- inspect the intended repository entry point and call `prepare_experiment` with an ordered argv;
- let Gemcp resolve repository defaults, the full commit SHA, resources, checks, cost, and idempotency;
- show the exact immutable proposal and wait for explicit human approval of its digest;
- call `submit_prepared_experiment` only with that proposal ID and digest.

`submit_experiment` remains an Advanced shell-command compatibility path. It still requires `get_project_options`, `get_project_cost`, a full pushed commit SHA, an exact command, a caller-managed idempotency key, and separate human approval.

After submission, record the Experiment ID and monitor it to a terminal state. Never create a replacement proposal merely because a response was delayed.
