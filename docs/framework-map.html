Gemcp v0.19.0

谁对谁做什么

用户只看研究问题和签字；Agent 只通过 MCP 维护 Graph 和提案；Gemcp 独占凭证、预算和调度；机器节点只执行已确认的 argv。在 Graph 上记一个节点，不会启动任何计算。

点上面的角色看职责

    刻意不存在的边

    • Agent 不连机器节点：没有 SSH tool，没有远程文件，没有日志推演指标
    • Owner 不直接改容器：控制台不下发任意主机命令
    • Self-hosted / AutoDL / Cloud SSH 互不兜底
    • 记录 Graph 节点不等于启动 GPU：只有确认后的 submit 才创建 Experiment

    Homonym

    「节点」是两件东西

    Machine node

    跑计算的机器

    组织资产。Owner 授权给 Project。调度器选中一台，占一卡或一个 SSH 进程。

    Self-hosted GPU PC Cloud SSH 主机 AutoDL Job
    Graph node

    研究主张

    Study 里的记录。时间轴用 occurred_at，不是 MCP 写入时间。有类型、有合法边。

    question hypothesis plan run result observation decision

    两套节点在 submit_prepared_experiment 才相交：控制面创建 Experiment，并在 Graph 写下 run。close_run 是唯一能写 result 的入口，边只能是 run produced result。没挂上 Graph 的 Experiment 在 Evidence 标 orphaned。

    Contract

    Graph 是执行合约，不是海报

    Agent 花钱前必须 get_next_actions。prepare_experiment 的 from_node_id 必须是 hypothesis 或 plan，并钉进 Owner 确认的 digest。

    Loop

    一次研究任务怎么走

    Owner
    Agent
    Gemcp
    Node

    Why

    这些约束不是风格问题

    确认 digest 才是花钱开关 submit 权限不是财务批准。prepare 不建 Experiment、不占预算。提交时再跑一遍 drift 检查。
    观测面只有 get_experiment log_tail 和 metrics.json 由 Runner / gemcp-node / SSH 轮询投影上来。Agent 不准从日志发明标量。
    工作负载是无权主体 容器或宿主机进程没有 Agent Token、Node Token、Deploy Key、Docker socket。Harness 若存在，也必须待在 MCP 这一侧。
    FIFO + 不可变 Attempt 一次 Experiment 多次基础设施重试会建新 Attempt，不会改原请求。命令失败不会换后端重跑。
    打开方式：浏览器打开本文件即可，不进控制台。内容按 v0.19.0 的控制面合约绘制；Cloud SSH 仍是实验通道。
